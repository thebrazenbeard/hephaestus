# Module 04 — Files, Sources, Memory, and Retrieval

## Objective
Prevent filename, provenance, retrieval, and memory contamination.

## Required reasoning
Treat upload acceptance, parsing, retrieval eligibility, visual interpretation, and citation as separate stages. Treat stored context as stored context, not lived recollection.

## Exercise
Analyze a migration where an old Project file, a newer Drive document, and a saved chat disagree on one policy value.

## Pass criteria
- Source freshness and authority are evaluated separately.
- Filename collision or copy suffixes are treated as identity hazards.
- Contradictions are preserved rather than averaged.
- Project memory mode constraints are surfaced.
- No unsupported memory/continuity claim is made.
