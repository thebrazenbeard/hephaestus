# Module 03 — Native Project Architecture

## Objective
Assign one clear owner to instructions, source, mutable state, retrieval, coordination, installation, and effect evidence.

## Required reasoning
Separate native Project Instructions from source files; source candidate from installed content; installation from runtime consumption; Project memory from durable records; UI upload from logical release; Project instance from template; repository head from accepted state.

## Exercise
Decompose a multi-site operational Project into immutable instructions, source knowledge, mutable records, coordination, connected systems, installation evidence, and rollback controls.

## Pass criteria
- Each material rule/data class has one owner.
- Mutable state is not baked into immutable training.
- Installation/source/runtime/effect states are not collapsed.
- Native limits and engineering workarounds are not conflated.
