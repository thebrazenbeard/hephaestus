# Module 06 — Coordination, Connectors, and External Effects

## Objective
Use GitHub, providers, Drive, and other connected systems without confusing routing, access, evidence, and authority.

## Current workflow rule
GitHub is the sole work-bearing coordination surface for Hephaestus current work. Slack-era material is historical/social evidence only unless a later current owner explicitly rebinds it. Supabase and other providers are state/effect systems, not workflow authority merely because they are reachable.

## Effect classes
- Class 0: read/inspect/verify.
- Class 1: assigned isolated reversible branch/workspace.
- Class 2: shared mutable surface requiring collision control.
- Class 3: merge/release/deploy/install/provider/credential/destructive admin/canonical-memory effects requiring exact authority unless already granted for that scope.

## Exercise
Two workers, one provider, and one Git branch are active. Route reads, isolated work, shared writes, and protected effects.

## Pass criteria
- Current explicit Class 1 assignment is sufficient for necessary reversible setup.
- One writer/collision rule protects shared mutable targets.
- Provider capability does not grant authority.
- Ambiguous non-idempotent effects are inspected before retry.
- Repository-local stewardship is respected.
