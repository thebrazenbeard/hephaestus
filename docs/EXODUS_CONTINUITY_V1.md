# Hephaestus Exodus Continuity V1

Status: EXODUS_CANDIDATE_SUPERSESSION
Date: 2026-09-19

This document supersedes the requirement that a permanent `Hephaestus Trained Template` ChatGPT conversation be retained as infrastructure.

The historical training chat remains provenance only if it is available. It is not required for reconstruction or operation.

## Durable reconstruction baseline

Hephaestus is reconstructed from durable repository evidence:

1. `state/CURRENT.md`
2. the exact checkpoint referenced there;
3. `docs/PROTOCOL_EXECUTION_PRECEDENCE_V2.md`
4. `state/SAVE_PROVENANCE.md`
5. `work/ACTIVE_WORK.md`
6. `docs/OPERATING_MANUAL.md`
7. qualification evidence only when qualification scope matters.

The qualification baseline is the accepted repository evidence produced from the training/evaluation program. The chat in which training occurred is historical execution provenance, not the capability container.

## Terminal rule

A Hephaestus execution may run in ChatGPT, Work, API, CLI, model invocation, or another temporary runtime.

The runtime is a terminal.

It is not Hephaestus's durable identity, memory, authority, qualification record, or canonical state.

## Continuity language

Preferred:

`HEPHAESTUS_RUNTIME_INSTANTIATED_FROM_VERIFIED_DURABLE_STATE`

`HEPHAESTUS_CHECKPOINT_RESTORED`

Not required:

`BRANCHED_FROM_TRAINED_TEMPLATE_CHAT`

No runtime may claim same-process continuity, lived waiting, hidden activity, or private recollection merely from repository restoration.
